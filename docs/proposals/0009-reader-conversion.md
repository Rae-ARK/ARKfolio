# 0009 — Turning visitors into readers (Stage 2 of the site review)

- **Status:** Proposed (design decisions made, not yet built)
- **Priority:** 2
- **Constraint:** SPA. Everything here is client-side or a static file.

## Problem

- The hero's main button goes to `/works` (a synopsis page), and the
  "Where to Read" cards on Home also go to `/works`, so the first click to
  an actual chapter is two or three clicks away.
- Three stories in three states (hiatus, ongoing, on break) leave a new
  visitor unsure where to start, and no single story suits everyone.
- The only ways to follow updates are X, YouTube and a `mailto:` feedback
  form.
- Store retailer buttons are all equal weight, although two carry caveats
  (Amazon via a Royal Road redirect; Books-A-Million is a search page).

## Decisions so far

- **No single flagship.** EPMC is the author's number-one pick, but it
  won't suit every reader, so the "where do I start" answer is chosen by
  *mood* rather than hard-coded (see change 1).
- **No mailing list.** The existing `mailto:` feedback form already covers
  getting in touch, so no list service is added and the site keeps
  collecting no personal data through this proposal.

## Proposed changes

1. **Mood card in the hero.** A card that cycles through short mood prompts,
   each pointing at one story. EPMC is the first and default card. Example
   shape: *"In the mood for something a bit different?"* → EPMC. Details:
   - Content lives in `data/works.ts` as a `moods` array (`prompt`,
     `workSlug`, optional `blurb`), so copy can change without touching
     components. The link target is the story's existing Royal Road
     `links` entry (external, `↗`), so no chapter-1 URL is needed.
   - Cross-fade/slide animation in `main.css` using the shared motion
     primitives from proposal 0007; collapses to an instant swap under
     `prefers-reduced-motion`.
   - Auto-advances slowly, pauses on hover and keyboard focus, and has
     previous/next controls plus dots so it is never the only way to see a
     card. Under reduced motion it does not auto-advance at all.
   - The rotating text is not an `aria-live` region (so it is not announced
     every few seconds); each card is a plain link with a clear label.
   - "Read the works" stays as the secondary button.
2. **"Where to Read" cards link straight to the platform** (Royal Road,
   Scribble Hub) instead of `/works`; the Works page stays reachable from
   the nav.
3. **Journal RSS feed.** A static `public/feed.xml`, generated by a small
   Node script in `scripts/` (no new dependency) that reads
   `data/journal.ts` and runs as part of `npm run build`. `<link
   rel="alternate" type="application/rss+xml">` in `index.html`, plus a
   discreet "RSS" link on the Journal page. Needs no account and collects
   no data.
4. **Store button hierarchy.** Amazon as the single primary "Buy"
   button; other retailers grouped under "Other retailers" with the
   existing per-retailer notes unchanged.

## Non-goals

- No change to retailer data or link targets.
- No mailing list or newsletter service.

## Open questions

- Mood copy: one prompt per story (and which stories appear at all).
  Needs the author's wording; a first pass can be drafted for review.
- Should the card cycle at all by default, or only change on interaction?
  The cycling version is specified above; a static card with a
  "Show me another" button is the lower-motion alternative.

## Verification

- Every home-page button reaches a readable chapter in one click.
- Mood card checked with keyboard only, with reduced motion on, at phone
  width and in dark theme.
- `feed.xml` validates and updates when `journal.ts` changes.
- Store layout checked at phone width and in dark theme.
