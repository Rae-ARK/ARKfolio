# 0009 — Turning visitors into readers (Stage 2 of the site review)

- **Status:** Proposed
- **Priority:** 2
- **Constraint:** SPA. Everything here is client-side or a static file.

## Problem

- The hero's main button goes to `/works` (a synopsis page), and the
  "Where to Read" cards on Home also go to `/works`, so the first click to
  an actual chapter is two or three clicks away.
- Three stories in three states (hiatus, ongoing, on break) leave a new
  visitor unsure where to start.
- The only ways to follow updates are X and a `mailto:` form.
- Store retailer buttons are all equal weight, although two carry caveats
  (Amazon via a Royal Road redirect; Books-A-Million is a search page).

## Proposed changes

1. **Direct "Start reading" hero button** linking out to the flagship
   story's first chapter on Royal Road (external link, `↗` per the
   site's external-link rule). "Read the works" becomes the secondary
   button.
2. **"Where to Read" cards link straight to the platform** (Royal Road,
   Scribble Hub) instead of `/works`; the Works page stays reachable from
   the nav.
3. **Newcomer line** under the hero lede, e.g. "New here? Start with
   *Summoned by Mistake*." Text lives in `data/works.ts` as a
   `startHere` flag so it follows the data.
4. **Journal RSS feed.** A static `public/feed.xml`, generated by a small
   Node script in `scripts/` (no new dependency) that reads
   `data/journal.ts` and runs as part of `npm run build`. `<link
   rel="alternate" type="application/rss+xml">` in `index.html`, plus a
   discreet "RSS" link on the Journal page. Needs no account and collects
   no data.
5. **Store button hierarchy.** Amazon as the single primary "Buy"
   button; other retailers grouped under "Other retailers" with the
   existing per-retailer notes unchanged.

## Non-goals

- No change to retailer data or link targets.
- No mailing list in this stage (see Open questions).

## Open questions

- Which story is the flagship, and which chapter URL is "chapter 1"?
- Mailing list: a hosted form (e.g. Buttondown, MailerLite) would be the
  first place the site collects personal data, so `PrivacyPolicyPage.vue`
  and the Play Store data disclosure would have to be updated at the same
  time. Decide after RSS has been in use for a while.

## Verification

- Every home-page button reaches a readable chapter in one click.
- `feed.xml` validates and updates when `journal.ts` changes.
- Store layout checked at phone width and in dark theme.
